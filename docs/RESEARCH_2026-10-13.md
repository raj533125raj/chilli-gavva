# Research: free platforms and agent frameworks (checked 2026-10-13)

Sources are official docs unless marked. Confidence: High = read in official docs; Medium = third-party or partial; Low = unverified.

## LLM
- Groq production models include `llama-3.1-8b-instant` and `openai/gpt-oss-20b`. Not shown as deprecated. Exact free-tier numbers for the 8B model are NOT on the public rate-limit page; read them in the Groq console limits page. Hitting a limit returns HTTP 429 with a `retry-after` header (engine now respects it). Whether the free tier allows commercial use is not stated: check the Groq terms before earning from it. Confidence: High for model list, Low for exact limits.
- Local option: Ollama on the user's Mac (no API limits) via smolagents/LiteLLM-style OpenAI-compatible endpoint. Not wired yet.

## GitHub
- Actions: standard runners are free for public repos; private repos get a plan quota (amount not on the page). 20 concurrent jobs on the Free plan. Jobs stop after 6 hours.
- Schedule: minimum every 5 minutes; delays at the start of each hour (use odd minutes); some queued runs can be dropped under load; runs only on the default branch; public repos get scheduled workflows auto-disabled after 60 days with no repository activity. So Actions cron is "near 24/7", not exact, and the repo needs activity (our runner commits its state).
- API limit with GITHUB_TOKEN: 1,000 requests/hour per repo.
- Pages: 1 GB site, 100 GB/month soft bandwidth, 10 builds/hour soft limit, commercial use not allowed (see above).

## Hugging Face
- Spaces: CPU Basic is free (2 vCPU, 16 GB RAM). Free Spaces sleep when idle, disk is not persistent, outbound network only on ports 80/443/8080. Static Spaces are free for everyone. One doc page said Gradio/Docker Spaces need a paid plan to create while also listing CPU Basic as free: contradictory, treat as UNVERIFIED (Low).
- Best fit for us: a static Space or Cloudflare Pages for the dashboard (read-only JSON), not an always-on agent host (Spaces sleep).
- smolagents (Apache-2.0): tiny code-as-action agent library, supports multi-agent, HF/local/LiteLLM models. Its LocalPythonExecutor is NOT a security sandbox: never run LLM-generated code with it on this machine.

## Cloudflare Pages (alternative host)
- Free: 500 builds/month, 20,000 files/site, 25 MiB max per file, 100 custom domains/project. Bandwidth not stated on the page. Good place for the dashboard and later the income site.

## Agent frameworks (third-party comparison, Medium confidence)
- LangGraph (MIT): checkpointing, resume after failure, audit trail. Heavier to learn.
- CrewAI (MIT): role/task/crew model, matches our pyramid roles. Fast version churn.
- smolagents (Apache-2.0): lightest, code-as-action, needs a real sandbox for execution.
- AutoGen: maintenance mode, avoid for new work.
## Decision for this project
Use our own small stdlib-only task queue + worker agents in SQLite (zero dependencies, inspectable, git-friendly, resumes after crashes like LangGraph checkpoints). Revisit CrewAI/LangGraph only if the worker graph gets complicated. Never execute LLM-generated code outside a sandbox: the self-improvement loop only edits files in a git branch, runs the test suite, and requires reviewer + tests (+ human approval for risky paths) before merging.
